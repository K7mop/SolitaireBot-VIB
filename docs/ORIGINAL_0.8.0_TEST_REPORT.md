# تقرير التحقق — مساعد السوليتير 0.8.0

**النطاق:** نسخة مصدر محلية مشتقة من أرشيف المستخدم 0.6.1، لا علاقة لهذا التسليم بتعديل مستودع بعيد.

## ما نفذ بالفعل

| الفحص | النتيجة |
|---|---|
| فحص الحزمة الأصلية وملفات Kotlin | تم |
| ترجمة جميع مصادر المحرك Kotlin JVM دون Android SDK | نجحت باستخدام `kotlinc 1.9.0` |
| فحوص `tests/run-core-smoke.sh` | **30/30 فحصًا ناجحًا** |
| تفسير XML للـ Manifest والموارد وإعداد Accessibility | نجح |
| فحص وصلات `LiveSession` و`VisualSafety` ومسارات حركة واحدة | مراجعة مصدرية، وليس اختبار جهاز |
| وجود ملفات JUnit | موجودة، **لم تُشغّل عبر Gradle** |

تتضمن فحوص المحرك: تحليل الأوراق، المنع عند تكرارها، قانونية النقلات إلى الأعمدة والأساسات، تتابع السحب الثلاثي، التعامل الحذر مع الحالات المجهولة، ترتيب الاقتراحات، المؤقت، التحقق البصري من حركة، وقيم إحداثيات معايرة المرجع.

## غير مكتمل التحقق

- لم يُبنَ APK: هذه البيئة تفتقر إلى `android.jar` وAndroid SDK وGradle الرسمي. لا يجوز اعتبار فحص Kotlin JVM نجاحًا في بناء تطبيق Android.
- لم يُشغَّل أي اختبار أندرويد أو جلسة حقيقية MediaProjection/Accessibility على محاكي أو هاتف؛ يجب اختبار قيود Android 14/15/16 فعليًا.
- لم تُختبر قوالب الرتب والأنواع على صور لعبة Battle Arena متعددة، ولا أداء التعرف على بطاقة مختلفة التكوين أو على شاشة 1080/1440.
- لم تتأكد جولة حقيقية ناجحة، ولم يُثبت استمرار الالتقاط لخمس دقائق في جهاز المستخدم.
- لم يتم التحقق من نقاط اللعبة الرسمية أو تخطيط يحسن الفوز عبر جولات فعلية.

## تجربة هاتف موصى بها

ابدأ بوضع المراقبة دون اللمس، ثم التقط صورة واضحة ومعايرة 13 منطقة، وعلّم قوالب حقيقية. تحقق من وجود اقتراح مستقر على إطارين، وشغّل إحدى النقلات بعد تفعيل الإذن صراحةً، ثم تأكد أن البرنامج لا يسجلها ناجحة حتى يراها في صورتين لاحقتين. جرّب انقطاع مشاركة الشاشة وقفل الهاتف وتغير أبعاد الالتقاط؛ يجب أن تُرفض النقلات القديمة، ويُلغى اعتماد المعايرة عند إعادة الجلسة أو تغيير الأبعاد، وأن تحتاج الجلسة الجديدة موافقة تسجيل منفصلة.
