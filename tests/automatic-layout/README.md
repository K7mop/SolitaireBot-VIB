# Automatic board reader regression (0.8.4)

This suite runs the **production** `AutoBoardSetup`, `CardVision`, `AutomaticRegionReader`,
`GlyphTemplates`, core rules and transition checks over generated RGB board images.
Only the Android Bitmap/Context boundaries are lightweight JVM doubles. Fixtures
are generated by `generate_fixtures.py` using Pillow and DejaVu Sans. They are not
screenshots from the user's phone or a benchmark of the target game's artwork.

Run from the project root:

```sh
JSON_JAR=/absolute/path/json.jar KOTLIN_BIN=/absolute/path/kotlinc sh tests/run-automatic-board-regression.sh
```

The fixtures cover first-image calibration, all seven exposed cards, canonical
foundation mapping from visible icons, independently visible empty regions,
matched stock backs, a foundation move, a newly empty column, a visible face-down
card, its flip, a stock draw, a visible circular-arrow recycle control, stale
sessions, malformed/occluded boards, pale placeholders, draw-one configuration,
footer exclusion, resolution changes and revocation of assumptions after an
unconfirmed gesture.

## Supported automatic setup

- A portrait screenshot, aspect ratio 1.25–2.6, at least 280×480 pixels.
- Seven evenly spaced columns spanning most of the screen width, each with a
  full light-colored exposed face in the first screenshot. First-deal layouts
  are the intended setup point; a partly completed board may not calibrate.
- Four foundations on the upper left with visible suit icons or recognized
  cards. They are reordered into clubs/spades/hearts/diamonds based on those
  symbols. An unlabelled/ambiguous foundation is not assigned a guessed suit.
- Waste between the foundations and the stock; stock at the far right.
- A distinguishable rectangular stock boundary and a common non-white playing
  surface. A colored, patterned back in the first image is needed to recognize
  exposed tableau backs later. Uniform/unknown back artwork remains unknown.
- Upright standard card indices with rank above suit, as documented in the
  bundled recognizer's own test directory.

This is an image-derived geometry detector with conservative local pattern
matching, not a universal object detector. Blank OCR output does not mean an
empty pile. Hidden identities are never inferred. A circular arrow is required
to infer a recycle affordance when a remaining redeal count is unavailable.

Passing these generated fixtures does not establish recognition accuracy,
gesture delivery, timing, scaling or overlay behavior on a physical phone or in
the user's game. A real, unobscured game screenshot and device run are needed
for that validation.


## 0.8.6 overlapping-white-border case

`connected_backs.png` adds white traces that join face-up cards to the blue back borders above them. The detector must infer the shared card height (rather than treating each tall connected white region as a differently sized card), find 7 aligned columns and 4 distinct foundation suit icons. The source user's actual screenshot is intentionally **not bundled** in the repository; it was evaluated separately with the production RGB recognition code.
